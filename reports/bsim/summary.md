# BSim pass: PS1 against the Saturn prerelease and DOS ports

Generated by `analysis/bsim/correlate.py`; reproduction steps in `analysis/bsim/README.md`. The strong, likely and string_only pairs, with their evidence, are in `pairs.json`; the full candidate set including weak pairs is written to `builds/bsim/pairs_all.json` (not committed; regenerate with the driver).

Settings: BSim template `medium_nosize`, one H2 database per platform; candidates at similarity >= 0.6 (queries run at 0.3 so string-proposed pairs carry a score). strong = similarity >= 0.7, significance >= 10, untied mutual best (or shared strings) and at least one corroboration (rare shared strings, >= 3 rare shared constants, call-graph agreement with an anchor pair, or link order between two neighbouring anchors); likely = the same BSim bar without corroboration (significance >= 15); string_only = rare shared strings, BSim below 0.6.

## Caveats

- Cross-architecture BSim (MIPS vs SH-2 vs x86) mostly finds small and mid-size leaf functions; similarity 1.0 on a small body means equal p-code feature sets, not equal code.
- Port function boundaries come from Ghidra flow analysis plus seeds (Saturn: jsr literal targets and pointer tables; DOS: data-to-code fixups) and a gap-filling pass; some port functions are fragments, which explains string pairs with no BSim score.
- Link order is the strongest independent signal for DOS (the PS1 order survives in the Watcom link); it is weak for Saturn (few anchors).
- `weak` pairs are leads only; most are generic small helpers matching many functions.
